面内推定評価ツール
管理者ガイド（構成と保守）

面内推定評価ツール（MATLAB アプリ）を管理する人向けに、アプリの作りと、 保守で起こりそうな作業の進め方・確かめ方・困ったときの対処をまとめます。

対象: アプリの管理者・保守担当 対象の版: MATLAB R2022b 更新日: 2026/10/22
01

Overview

目的と対象

このツールは、アライメント計測の Excel（または CSV）を読み込み、一部の Shot の計測値から残りの Shot の値を推定して、 推定の手法・学習 Shot の選び方を比べる画面つきアプリです。利用者の操作は Windows 手順書と PowerPoint の手順書で説明しています。 この資料は、アプリを直す・配る・不具合を調べる管理者のためのものです。

Audience

対象者

MATLAB の関数を読んで直せる人。統計・推定手法の細部まで知らなくても、この資料の「変更する場所」の表から直す場所を探せます。

Scope

対象範囲

リポジトリの matlab_app フォルダ（画面・計算・テスト・exe の作成・手順書）。Python 版（src）は照合の基準値としてだけ使います。

Goal

この資料でできること

直す場所が分かり、直した後に自動テスト・サンプルデータ・exe で確かめて、利用者に配れる状態にすること。

02

Prerequisites

作業前の確認

  • MATLAB R2022b（本体だけ。Toolbox は使っていません）。exe を作るときだけ MATLAB Compiler が要ります。
  • 直す前の matlab_app フォルダを残しておく（Git を使うなら、作業用のブランチを作る）。
  • 自動テストが全件成功することを、直す前に一度確かめる（6. 保守の作業の「テストを実行する」）。失敗が直す前からあるのか、直したせいかを区別するためです。
  • 確かめに使うデータは、同梱の模擬データ（sample_data/sample_alignment.xlsx）にする。
!

実データ・社内情報の扱い

このリポジトリは公開設定です。会社の計測データ、評価結果・推定値の Excel、社内の装置名などを リポジトリに入れないでください。不具合を再現するときは、模擬データか、値を変えたデータを使います。

✓

会社で直すときの進め方

1回の変更は1つの関数（または近い数個）に絞ると、テストで確かめやすく、元に戻すのも簡単です。 GitHub Copilot に相談するときは、直したい関数と、この資料の該当する表の行だけを渡し、 一度に大きく書き換えさせないでください（従量課金の利用料を抑えるためにも、依頼は具体的に1つずつ）。

Workflow

→
2学習 ShotbuildPlanSpecs・planTrainingShots
→

→
4評価・集計runEvaluation・summarizeResults
→
5書き出しexportResults・exportEstimates
段階すること主な関数
読み込みExcel・CSV を読み、列を標準の項目に対応づけ、座標の単位をそろえ、行を除き、Wafer（工程・装置・ロット・測定日時で区別）ごとにまとめる。Scan 方向が無ければ規則で付ける。絶対座標だけのデータは Shot 中心を決め（shotNo の点の平均、または点を1つずつ Shot に）、1変数（膜厚など）は値を X 成分に入れて Y 成分を使わないreadMeasurementFile・guessColumnMapping・checkCoordinateUnits・prepareData（shotsFromAbsolute・pointCellSize）・standardColumns（必須の項目）・valueSpec・directionRules
学習 Shot学習 Shot 数（または計測率）ごとに、制約付き I 最適・D 最適・ランダム・Excel ファイルで指定（人が決めたパターン・優先順。Mark 単位も。以前の手動・ファイルの優先順をまとめたもの）・Mark 単位の I 最適・D 最適（計測率でのスイープ、Shot ごとに n 点の必須はオプション）で学習 Shot（Mark 単位なら学習 Mark）を選ぶ。選び方は複数選べて、学習パターンの名前の先頭に選び方が付く。同じ配置の Wafer は同じ選び方を使い回すbuildPlanSpecs・cachedTrainingPlan・planTrainingShots・constrainedIOptimal・exchangeDesign（D 最適・Mark 単位の交換法）・readLayoutPlans・parseLayoutPlans・upgradeLayoutSettings（以前の手動・優先順の設定を直す）・trainingMarks・designCriteria
推定手法ごとに、学習 Shot の計測値から学習しなかった Shot の値を X・Y 別に推定するbuildMethodList・activeMethods（質的変数を1つだけ使う手法を足す singleFactorMethods。推定では singleFactorSettings。質的変数の組を変えて条件を足した手法は tagFactorSet・factorSetKey の _fs-）・estimateWafer・+models の関数
評価・集計評価点（学習しなかった Shot の有効な Mark）の RMSE・MAE・R² などと、Overlay 補正の残差の変化を求め、手法 × 学習パターンで集計する。評価済みの結果に手法・学習パターンを足す（済んだ組み合わせは計算しない）。行ごとの評価点の推定値を残し、評価点を半径・Shot の条件で絞って指標を計算し直すrunEvaluation（"extend" で追加）・extensionConflicts・computeMetrics・compactEstimate・filterResults・pointFilterMask・overlayCorrection・summarizeResults・pairedComparison
未知の座標の推定計測していない点を計測値の無い Mark として Wafer に足し、評価と同じ推定で値を求める（Wafer × 学習データの組み合わせごとに一括）。学習点の凸包の外を外挿として知らせ、300 mm Wafer の外の点は推定せず 0 にする。推定した後に、実測値・推定値をまとめて重ね合わせ補正値（係数）を求めるpredictTargets・estimateWafer・targetOverlayCorrection（設計行列は overlayDesign）
Shot 高次補正の評価計測値・未知の座標の推定値・Excel の値で、Shot 高次補正の式（ASML・Canon・Nikon と、k1〜k38 のカスタムの式）の k パラメータを、Wafer 内で共通・Scan 方向ごと・行の偶奇ごと・Shot ごとのいずれかのくくりで求める（Scan 方向ごと・行の偶奇ごとは、組ごとの k と Wafer で共通の Wafer 成分を一緒に解く）。VIF で使う項を選び、点の数が最も少ない k の組で決められない項は k の小さい順に絞り、ロバスト回帰（Huber・LAD）と選んだ次数の項だけの正則化（L2・L1）で解き、Shot ごとの1次（k1〜k6）の補正と |平均|+3σ・|残差| の 95% 点・中央値で比べる（内周・外周に分けても出す）。外周の Shot（Shot 中心の半径で決める）だけ別の式にでき、Shot ごとのときは Wafer 成分（5次まで）を先に引く。くくり・λ のスイープ・回帰・保存した項の組み合わせをまとめて比べ、2つの条件の Shot ごとの残差を比べて改善・悪化した Shot を示し、Wafer ごとの k・残差を比べ、Shot の形をグリッドで描く。残差を Wafer 線形・Shot 共通・Shot・残りに分け、k パラメータの項ごとの分を出す。補正値・補正残差を、計測データの形（読み直せる）・Shot ごとの k の横並び・補正の比較の全条件で CSV・Excel に書き出す。Excel・CSV は列の名前が自由で、読んだ後で項目ごとに列を選ぶshotHighOrder（highOrderOptions・highOrderTerms・highOrderVif（varianceInflation）・robustRidgeFit）・compareHighOrderConditions・compareHighOrderShots・decomposeHighOrderResidual・highOrderMeasurementTable・highOrderShotTable・highOrderConditionTable・writeHighOrderTable・highOrderModelAt・plot.shotGridMap・highOrderUnitPoints・highOrderTargetPoints・readHighOrderFile・highOrderColumns・prepareHighOrderData・exportHighOrder
書き出し・読み込み評価結果・推定値を Excel に書き出す。書き出した Excel を読み込んで、計測ファイルなしで表・グラフ・マップを描き直すexportResults・exportEstimates・importResults・importEstimates

i

設定の画面を直すときの4つの関数

「2. 評価の設定」の部品を足すときは、次の4つ（どれも +appui/SettingsTab.m）をそろえて直します： settingsToControls（設定 → 画面）、controlsToSettings（画面 → 設定）、 validateSettings（入力の確認と赤字の説明）、updateEnabled（使えない部品を灰色にする）。 1つでも抜けると、設定ファイルの保存・読み込みで値が戻らない不具合になります。

Troubleshooting

困ったとき

起動すると「関数または変数が認識されません」と出る

現在のフォルダが matlab_app になっているか確かめます。alignest.○○ の関数は、+alignest フォルダの親（matlab_app）がパスにあると使えます。runAlignmentEstimationApp で起動してください。

読み込みで「必要な列がありません」と出る

画面の「列の対応」で、足りない項目にファイルの列を選びます。毎回同じなら、ファイルの列名を標準の項目名にそろえるか、guessColumnMapping に別名との対応を足します（今は列名の完全一致と、大文字・小文字だけの違いを自動で対応づけます）。必須の項目は standardColumns の required で決まります。

評価に時間がかかりすぎる

手法・学習 Shot 数・Wafer の数を減らします。進み具合の画面の「一時中断」で止めても、途中までの結果は残り、「続きから再開」で残りを計算できます。時間の目安は 1 条件 2 秒の一律の値なので、実際とずれるときは「処理時間を記録する」で手法ごとの時間を測り、SECONDS_PER_RUN を見直します。「4. 結果一覧」の「処理時間の内訳」で、学習パターンの作成（I 最適の交換法）・学習・推論のどれに時間がかかっているかを見られます。交換法の初期配置の数は、時間にほぼ比例します（README の「交換法の初期配置の数と計算時間」）。評価の後に手法・学習 Shot 数を足すときは「条件を追加して評価」を使うと、済んだ組み合わせを計算し直しません。

「条件を追加して評価」で「評価したときと次の設定が違う」と出る

追加できるのは、手法の選択と学習パターンの数（学習 Shot 数・計測率の範囲、Excel で指定したパターン、ランダムの繰り返し回数）だけです。表示された設定（データの読み込み・質的変数・学習 Shot の選び方と制約・評価の条件・Overlay 補正・手法の細かい設定）を評価したときに戻すか、「評価を始める」で最初から計算します。判定は extensionConflicts にあります。

評価の結果が大きく、メモリが足りなくなる

評価の結果には、絞り込みの計算し直しとマップのために、行（Wafer × 学習パターン × 手法）ごとの評価点の推定値（results.pointEstimates。1 行あたり およそ 評価点の数 × 2 軸 × 16 バイト。模擬データでは 1 行 13 KB 程度）を持ちます。行が非常に多いときは、手法・学習パターン・Wafer を分けて評価し、結果の Excel に書き出してから次を評価してください。

Excel に書き出せない

同じ名前のファイルを Excel で開いていると置き換えられません。閉じてからもう一度書き出します。推定値の「すべての手法・学習パターン・Wafer」は行数が Excel の上限を超えることがあるので、範囲を絞ってください。

書き出した評価結果・推定値の Excel を読み込めない

このアプリで書き出したファイルか、シート名や見出し（「Waferごと」「推定値」など）を Excel で変えていないか確かめます。推定値の Excel は、先に「結果を読み込む…」で同じ評価の評価結果を読み込んでから読み込みます。マップに「書き出した範囲の外」と出るときは、推定値を書き出したときの範囲（手法・学習パターン・Wafer）に、その組み合わせが入っていません。

補正の式で赤字のエラーが出る

項を + でつなぎ、各項は係数と x・y のべきの積で書きます（例：k1 + k3*x + k5*y + k7*x^2 + k9*x*y）。かっこ・2x のような * の省略・x1 のような書き方は使えません。式の読み方は parseCorrectionFormula にあります。

「最適化または Backfitting が反復上限内に収束しませんでした」と記録される

最終反復の推定値で評価を続けています。多く出るときは、学習 Shot 数が少なすぎないか確かめ、必要なら設定の methods.options.gprMaxIterations・backfitMaxIterations を増やします（時間は増えます）。

テストが失敗する

直す前の状態でも失敗するかを、元のフォルダで確かめます。直す前から失敗するなら環境（MATLAB の版・言語の設定）の違い、直した後だけなら変更が原因です。失敗の表示の「期待した値」と「実際の値」を比べ、意図した変更ならテストの期待値を、意図しない変更なら関数を直します。

exe が起動しない

exe を使う PC の MATLAB Runtime が、exe を作った MATLAB と同じ版（R2022b）か確かめます。会社の PC で exe の実行が制限されている場合は、情報システムの担当に確認してください。

i

解決しない場合

エラーの表示（「何が起きたか・なぜか・次にどうするか」の文）と、操作したタブ・ボタン、使った設定ファイルを残して、アプリの管理者どうしで共有してください。実データは共有せず、模擬データで再現できるか先に確かめます。
