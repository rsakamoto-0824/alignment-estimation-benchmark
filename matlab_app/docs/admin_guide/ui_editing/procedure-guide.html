01

Administrator procedure

1. 目的と対象

「面内推定評価ツール」の画面を管理者が変更するときに、どのファイルを開き、どの文字・設定を編集し、何を確認して配布するかを説明します。対象はローカルの最新版ソースです。過去の管理者仕様書の固定版（84ca419）とは対象版が異なります。

編集するもの

MATLABの AlignmentEstimationApp.m。画面の名前、ボタン、入力欄、配置とイベント処理をコードで定義しています。

編集できる環境

ソース一式とMATLABを持つ管理者のPC。配布済みexeとMATLAB Runtimeだけでは、元の画面コードを編集できません。

完了した状態

変更した画面を再起動して確認し、読み込み・設定・小規模評価が通ることを確認。exe利用者へは作り直した実行ファイルを配布します。

i

App Designerの「Design View」で部品を動かすアプリではありません

このリポジトリの画面は classdef ... < handle と uifigure / uigridlayout で作るプログラム型UIです。.mlapp のデザイン画面へ変換して編集する手順は使いません。

02

Administrator procedure

2. 作業前の確認

  • 編集用フォルダとして、アプリのソース一式をコピーします。既存の変更がある場合は残し、変更前のファイルも別名で保管します。
  • ソースの matlab_app に、AlignmentEstimationApp.m、runAlignmentEstimationApp.m、+alignest、help、sample_data、tests があることを確認します。
  • MATLAB本体で編集・起動します。この資料の描画確認はR2022b Update 1。Windows用exe作成にはWindows PC上のMATLAB Compilerが必要です。
  • 動作確認には同梱の sample_data/sample_alignment.csv を使います。実運用の計測ファイルを変更例へ混ぜません。
確認項目この資料の条件
ソース基準a8eb43a6ccedf4d9fd78c08677fa1faac6dc44dd（2026-10-26更新）。作成時の画面クラスはこのコミットと一致。
資料作成日2026-10-27
通常の運用先Windows 11を想定。会社の手順はMATLABと既存のファイル管理だけで実施でき、デスクトップ型AIを必要としません。
スクリーンショットMac上のR2022bで、アプリの公開captureTab機能から実際のUIを描画・保存。OSの外枠・フォントはWindowsと異なります。
コード編集画面ソース検索の画像のみMacのCotEditorです。MATLABデスクトップの起動画像は取得できなかったため、MATLABエディターに見せかけていません。Windowsのエディター操作は実機未撮影です。
変更例説明用コピーでボタン名・列幅・説明行を変更。アプリ本体と計算ロジックはこの資料作成では変更していません。
i

最初の変更は文字だけに絞る

画面の文字を変える場合と、計算へ渡す値を変える場合では確認範囲が違います。まず第5章のボタン名変更で、保存→閉じる→再起動の流れを確かめてください。

04

Administrator procedure

4. ファイルを開き、変更箇所を探す

  1. MATLABで編集用のmatlab_appフォルダを選びます。

    現在のフォルダーから移動するか、次のコードをコマンドウィンドウで実行します。「matlab_app」そのものを選びます。

  2. どのコピーが読み込まれるかを確認します。

    which AlignmentEstimationApp -all の先頭が編集用コピーを指すことを確認。別フォルダが先頭なら、そのコピーを閉じてパスを整理します。

  3. 画面定義ファイルを開きます。

    edit AlignmentEstimationApp で開き、検索（WindowsはCtrl+F、MacはCmd+F）へ function buildDataTab と入力します。呼び出し箇所ではなく関数定義へ移動します。

  4. 変更前を退避します。

    下のバックアップ例を実行し、バックアップファイルの存在を確認。classdef AlignmentEstimationApp とファイル名の組はそのままにします。

appFolder = uigetdir(pwd, '編集用コピーの matlab_app を選ぶ');
if isequal(appFolder, 0), return; end
cd(appFolder)
addpath(appFolder)
which AlignmentEstimationApp -all
edit AlignmentEstimationApp
backupName = ['AlignmentEstimationApp_before_' datestr(now,'yyyymmdd_HHMMSS') '.m'];
copyfile('AlignmentEstimationApp.m', backupName)
isfile(backupName)  % 1なら存在します
i

行番号は目印です

機能追加で行番号はずれます。画面に出ている日本語→部品名（例：c.chooseFile）→所属するbuild関数→コールバック、の順に追うと対象を見つけやすくなります。

05

Administrator procedure

5. ボタン・タブの文字を変える

最初に、ファイル選択ボタンの名前だけを変えます。計算やファイル選択の動作は変えません。

  1. c.chooseFile = uibutton を検索します。

    buildDataTab内にあることを確認してください。

  2. Text の文字列だけを変更します。

    「ファイルを選ぶ…」を「計測ファイルを選ぶ…」に変更。c.chooseFile と ButtonPushedFcn は変えません。

  3. 保存し、現在のアプリ画面を閉じて開き直します。

    MATLABのクラスファイルのRunボタンに頼らず、コマンドウィンドウで app = AlignmentEstimationApp(); を実行します。実行中の画面は、ソースを保存しただけでは作り直されません。

  4. 新しい名前のボタンを押し、ファイル選択画面が開くことを確認します。

    キャンセルで元の画面へ戻れることも確認します。

変更前

c.chooseFile = uibutton(fileGrid, 'Text', 'ファイルを選ぶ…', ...
    'ButtonPushedFcn', @(~, ~) app.onChooseFile());

変更後

c.chooseFile = uibutton(fileGrid, 'Text', '計測ファイルを選ぶ…', ...
    'ButtonPushedFcn', @(~, ~) app.onChooseFile());
変えたい文字プロパティ残すもの
ボタン・ラベル・チェックボックスの文字Text部品名・コールバック・内部の値。
タブ・パネルの見出しTitleapp.Tabsのdata/settings等のキー。
ウィンドウの名前APP_TITLEクラス名、起動関数名、exeの内部名は別に扱う。
カーソルを置くと出る説明Tooltip入力値の意味・単位と説明を一致させる。
i

検索と置換は、最初は1件ずつ

日本語が同じでも別の画面やエラーメッセージで使う場合があります。「すべて置換」で内部名まで変えると、動作やテストを壊すことがあります。

Administrator procedure

6. 幅・高さ・配置を変える

このアプリでは、部品をマウスでドラッグする代わりに、親のグリッドの列幅・行高と、その部品の行・列番号を変更します。

指定意味今回の具体例
uigridlayout(parent, [行数, 列数])部品を並べる区画数fileGridは変更前が6行×4列。
ColumnWidth各列の幅数値はpx。fitは内容に合わせる。1xは残りを配分し、2xなら1xの2倍。
RowHeight各行の高さfitで文字量に追従。行を追加したら要素数も確認。
Layout.Row / Layout.Column部品を置く区画Row=3、Column=1なら3行1列。Column=[1,4]なら4列をまたぐ。
Padding / RowSpacing / ColumnSpacing外側の余白・区画の間隔詰めすぎると文字が接触し、広げすぎると入力欄が狭くなる。

根拠：AlignmentEstimationApp.m 1418〜1421行（対象版）。行番号より検索語を優先してください。

grid = uigridlayout(app.Tabs.data, [2, 1], 'RowHeight', {'fit', '1x'}, 'Padding', 12, 'RowSpacing', 12);
            filePanel = uipanel(grid, 'Title', '計測データのファイル');
            fileGrid = uigridlayout(filePanel, [6, 4], 'ColumnWidth', {'fit', '1x', 260, 300}, ...
                'RowHeight', {'fit', 'fit', 'fit', 'fit', 'fit', 'fit'}, 'Padding', 10);
  1. 対象の部品の親を確認します。

    c.chooseFile の親は fileGrid。画面全体のrootや別のタブのgridを変更しないよう注意します。

  2. fileGridのColumnWidthを変更します。

    この例は {300, '1x', 280, 320}。1列目を300px、2列目を残り、3列目を280px、4列目を320pxにします。4列なので値は4個です。

  3. 部品の位置を変更するときは行・列を指定します。

    place(c.chooseFile, 3, 1) は既存の2行のLayout指定と同じ働きです。親グリッドの範囲を超えず、他部品と重ねないようにします。

  4. 再起動し、幅を変えて確認します。

    最大化した画面だけでなく、会社PCで使う通常のウィンドウ幅で、ファイル名・説明・長い手法名が読めるか確認します。固定幅が多い場合は狭い領域が残らないかを見ます。

% 表示領域を4列で配分する例
'ColumnWidth', {300, '1x', 280, 320}

% 部品をグリッド内へ配置する共通関数
place(c.chooseFile, 3, 1);
% 内部では Layout.Row = 3; Layout.Column = 1; を指定
i

親の幅を変えると、その列を共有する部品も動きます

ファイル選択ボタンだけでなく、ファイル名・Scan方向・座標定義なども同じグリッドを使います。変更箇所だけを見ず、上段の入力領域全体を確認します。

7. 説明文を1行追加する

説明文だけを追加する例です。画面に表示するだけなので、Settingsへの項目追加や計算の修正は不要です。第5・6章と合わせた変更例を、実際に描画して確認しました。

  1. fileGridを7行へ増やします。

    [6, 4] を [7, 4] にし、RowHeight に7個目の 'fit' を追加します。

  2. fileGrid生成の直後へ、説明用ラベルを追加します。

    以下のコードを入力します。adminNote はこの関数内だけの部品名で、配置は7行目・1〜4列をまとめて使用します。

  3. 保存して再起動します。

    新しい注意文が座標定義の下に表示され、既存の6行が押しつぶされないことを確認します。

  4. ライト・ダーク両方で確認します。

    補足の文字色には固定の黒ではなく app.Palette.muted を使います。

fileGrid = uigridlayout(filePanel, [7, 4], ...
    'ColumnWidth', {300, '1x', 280, 320}, ...
    'RowHeight', {'fit','fit','fit','fit','fit','fit','fit'}, ...
    'Padding', 10);
adminNote = uilabel(fileGrid, ...
    'Text', '管理者向け注意：読み込み前に列と単位を確認してください。', ...
    'WordWrap', 'on', 'FontColor', app.Palette.muted);
place(adminNote, 7, [1, 4]);
i

後から書き換える部品はControlsへ登録する

表示だけならローカル変数で足ります。別の関数から文字やEnableを変更する場合は c.adminNote として作り、build関数末尾の app.Controls = mergeStruct(app.Controls, c) に含めて参照します。名前を他の部品と重複させないでください。

8. 選択肢・初期値・設定をつなぐ

選択肢の「表示名」と「内部値」を区別する

例として、学習Shotの選び方は表示を Items、処理へ渡すキーを ItemsData で定義しています。以下は既存7項目のうち、先頭2項目の対応です。元の7項目を2項目に置き換える手順ではありません。

Itemsの表示名同じ位置のItemsData
制約付き I 最適（前回の評価と同じ）ioptimal
制約付き D 最適doptimal
  1. 表示名だけを変える場合

    該当する Items の文字だけを変えます。並び順・要素数と、対応する ItemsData をそろえます。内部値 ioptimal などを日本語へ変えないでください。

  2. 新しい選択肢を増やす場合

    画面へ選択肢を足すだけでは計算できません。ItemsData、controlsToSettings、設定の既定値、検証、+alignestの分岐・手法一覧・書き出し・テストまで対応させます。

  3. 起動時の値だけ変える場合

    先に「設定を保存…」でJSONを作り、必要な値を変更します。共通の初期設定は、起動時の現在のフォルダに alignment_estimation_defaults.json を置く方法もあります。画面の文言・配置はJSONでは変更できません。

既存の有効半径を例にした、画面と設定の往復

段階コード内の場所確認する内容
部品を作るbuildDataTabc.validRadiusのValue・Limits・ValueChangedFcn。
設定→画面settingsToControlsc.validRadius.Value = s.data.validRadiusMm。
画面→設定controlsToSettingss.data.validRadiusMm = c.validRadius.Value。
既定値・型+alignest/defaultSettings.m設定項目を定義。新規項目はここに存在しないとloadSettingsで無視される。
保存・読込+alignest/saveSettings.m / loadSettings.m保存はJSON化、読込は既定項目に重ねる。古い設定ファイルでも動くか確認。
実行・再描画コールバック / +alignest / refresh関数変更した条件が古い結果と混ざらず、必要な再計算が行われること。
{
  "data": {
    "validRadiusMm": 149
  }
}
i

初期値が戻るときに見る順番

defaultSettings → 現在のフォルダの既定JSON → 個別に読み込んだ設定 → settingsToControls を確認します。UI作成時のValueだけ変えても、後の同期でSettingsの値へ戻ることがあります。Controls 自体をJSONへ保存しないでください。

Administrator procedure

9. ボタンを押した後の処理を確認する

コールバックは「クリックしたとき・値を変えたときに呼ぶ処理」です。文字や配置だけの変更では、この接続を保ちます。

'ButtonPushedFcn', @(~, ~) app.onChooseFile()

上の @(~, ~) は、MATLABから渡される発生元とイベントをこの処理では使わない指定です。ボタン名を変えても、呼び出し先 onChooseFile を変える必要はありません。

根拠：AlignmentEstimationApp.m 1621〜1631行（対象版）。行番号より検索語を優先してください。

function onChooseFile(app)
            [fileName, folder] = uigetfile({'*.xlsx;*.xlsm;*.xls;*.csv', '計測データ (*.xlsx, *.xlsm, *.xls, *.csv)'}, ...
                '計測データのファイルを選ぶ');
            figure(app.Figure);
            if isequal(fileName, 0)
                return
            end
            runWithAlert(app, @() app.loadFile(fullfile(folder, fileName)), "ファイルを読み込めませんでした", ...
                "ファイルが Excel で開かれていないか、1行目が項目名になっているかを確かめてください。");
        end
部品・操作主な接続先変更後に確認すること
ファイル選択onChooseFile → loadFileダイアログ、キャンセル、読込エラーの表示。
列対応の確定onApplyMapping → applyMapping選んだ列・単位でデータを作り直す。
入力データ条件を変えるonDataOptionsChanged / invalidatePreparedData以前に整理したデータをそのまま使わない。
評価設定を変えるonSettingsChanged検証→controlsToSettings→有効/無効の更新→実行概要の更新。
評価を始めるonRun → runEvaluationNow等進行状況、エラー、結果表示。重い処理をbuild関数へ入れない。
i

Valueを代入しただけではイベントが発火しない場合がある

動作確認コードから app.Controls.xxx.Value = ... と設定する操作は、利用者が画面で値を変える操作と同じとは限りません。公開APIの app.setSettings(s) を使うか、対象のValueChangedFcnが何を更新するか確認します。

新しい「計算へ渡す入力」を追加するときの順番

  1. 設定項目を決める。

    defaultSettingsへ名前・型・単位・初期値を追加。数値の範囲とエラー時の扱いを決めます。

  2. UIを作ってControlsへ登録する。

    親グリッドの行数と配置も合わせて直します。

  3. 設定の往復と検証を追加する。

    settingsToControls、controlsToSettings、validateSettings等の該当処理へつなぎます。入力条件が変わればデータや結果の作り直しも必要です。

  4. 計算と保存へ渡っているか確認する。

    +alignestの該当関数が新しい値を実際に使い、設定の保存・再読込で値が残り、旧JSONでも起動することを確認します。

10

Administrator procedure

10. 文字・色・表示を調整する

文字の大きさ

冒頭の定数 FONT_SIZE=16、AXES_FONT_SIZE=13、TABLE_FONT_SIZE=13 などを確認します。コンストラクター末尾でFontSizeをまとめて適用し、表などは例外のサイズを上書きしています。部品を作った行だけでFontSizeを指定しても、後で変わる場合があります。

色・テーマ

themePalette がライト・ダークの背景、文字、補足、エラー、入力欄、ボタンの色をまとめています。切替処理は setTheme → applyTheme です。新しい部品も app.Palette.text / muted / error など役割で色を指定します。

調整したいもの主な場所注意
画面全体の基準文字FONT_SIZEとコンストラクター末尾部品ごとの例外サイズを確認。
表の列幅ColumnWidth / METHOD_COLUMN_WIDTH等長い手法名と数値の両方が読める幅。
図の文字AXES_FONT_SIZE / SMALL_AXES_FONT_SIZEグラフ再描画後にも適用されるか。
ウィンドウの初期サイズFIGURE_SIZE / figurePosition本PCの確認画像は1600×1000指定。既定は1440×900で、小さい画面に合わせて調整される。
ヘルプ本文help/help.html / buildHelpTabUIの名称を変えたらヘルプ内の説明も合わせる。
i

色の設定を変えると利用者全体の見た目が変わります

themePaletteの共通色はアプリ全体に使われます。1個のエラー文だけのつもりで共通色を変更しないようにし、ライト・ダークの両方で表・図・警告を見直します。

Administrator procedure

11. 保存・再起動・動作確認

  1. ファイルを保存します。

    WindowsはCtrl+S、MacはCmd+S。ファイル名とclassdefの名前を変えていないことを確認します。

  2. MATLABで構文を確認します。

    checkcode のメッセージは該当行を開いて確認。表示された警告のすべてを無条件に消すのではなく、変更箇所との関係を確かめます。

  3. アプリを閉じて新しいインスタンスを起動します。

    app変数で起動した画面は下のdelete/clearの例を使用。ほかの作業中の変数を消す clear all は使いません。

  4. 見た目・操作・設定の保存を確認します。

    下のチェックリストを実施。入力値を変える修正では設定をJSONに保存し、再読込して同じ値に戻ることも確認します。

  5. サンプルで小規模評価します。

    同梱CSVを読み込み、短時間で終わる条件で実行。変更前と同じ入力・設定で比較し、見た目だけの変更なら評価値が変わらないことを確認します。

    delete(app)

Administrator procedure

12. Windows版を作り直す・元に戻す

MATLABで直接使う利用者へ配る場合

変更したソースと必要なパッケージを配布し、起動元が新しいコピーになっているか which AlignmentEstimationApp -all で確認します。ソースファイルだけ置き換えたまま、古い画面を開き続けないでください。

Windowsのexeを使う利用者へ配る場合

  1. 確認したソース一式をWindowsのビルド用PCへ移します。

    MATLAB Compilerを利用できるPCで実行します。MacでWindows用exeは作れません。

  2. matlab_appを現在のフォルダにしてビルドします。

    最初は実行ファイルのみを作ります。必要な場合だけインストーラーを作成します。

  3. build/output/win64を確認します。

    新しいAlignmentEstimationApp.exeを別の確認フォルダで起動。対応するMATLAB Runtimeを使用して、MATLAB本体から起動したときと同じ画面になるか確認します。

  4. 配布版の名前・日時・ソース版を記録します。

    配布先の古いショートカットが旧exeを指していないか、既定JSONの作業フォルダーが変わっていないかも確認します。

addpath build
buildStandaloneApp

% 必要な場合のみ、Runtimeを内包したインストーラーも作成
buildStandaloneApp(makeInstaller=true, runtimeDelivery="installer")

変更を戻す手順

  1. 変更したアプリ画面を閉じます。

    利用中の画面を終了し、編集用ソースとバックアップを見比べます。

  2. 対象ファイルだけを変更前へ戻します。

    今回の例はAlignmentEstimationApp.mだけ。ほかの人の変更や別の作業をまとめて取り消さず、変更したファイル・行だけを戻します。

  3. 再起動して確認します。

    exeで配布済みの場合は、旧版exeを戻すか、復元したソースから再ビルドします。ソースを戻しただけでは、既に作成したexeの中身は変わりません。

Administrator procedure

13. 困ったとき・根拠ファイル

保存したのに文字が変わらない

古いアプリ画面が残っていないか、whichで編集用コピーが先頭かを確認。画面を閉じ、クラスをクリアして再起動します。配布exeは再ビルドが必要です。

部品が重なる・文字が切れる

親グリッド、ColumnWidth、RowHeight、Layout.Row/Columnを確認します。行を足した場合は行数とRowHeightをそろえ、WordWrapや固定幅の合計を確認します。

初期値を変えたのに元へ戻る

部品のValueだけでなくSettingsの既定値・既定JSON・settingsToControlsを確認します。loadSettingsはdefaultSettingsにない項目を無視します。

選択肢は表示されるが計算できない

ItemsDataのキーと+alignest側の対応処理が一致しているか確認。表示名の追加だけでは新しい手法は実装されません。

ボタンを押すと入力引数やメソッドのエラーになる

ButtonPushedFcn/ValueChangedFcnの呼び出し先、引数、appのスコープを確認。別の部品からコピーしたコールバックのままになっていないかを見ます。

ダークモードで追加した文字だけ見えない

固定色ではなくPaletteの役割色を使い、applyThemeが扱える部品か確認。新しい種類の部品を追加する場合はテーマ切替の対応も確認します。

画面作成時にclassdefやendのエラーが出る

引用符、括弧、...、カンマ、endの数を変更前と比較。まず1つ前の動く状態へ戻し、変更を1種類ずつ適用します。

Compilerがない・MacでWindows版が作れない

ソース編集とMATLAB内での起動は実施できます。Windows用exeの再作成は、WindowsとMATLAB Compilerを利用できるビルド担当PCで行います。
